# 다, 너의 단어

일하는 사람을 위한 7개 분야의 실무 언어 사전. HTML·CSS·JavaScript만 사용하며, 외부 AI·검색 API와 서버 데이터베이스 없이 동작합니다.

## 실행

`index.html`을 브라우저로 여세요. 같은 폴더의 CSS·JS 파일을 함께 보관해야 합니다.
개발 미리보기는 이 폴더에서 `python3 -m http.server 8934 --bind 127.0.0.1`을 실행하고 http://127.0.0.1:8934/index.html 을 엽니다.

파일 주소의 저장 정책은 브라우저마다 다릅니다. `localhost`, `127.0.0.1`, 다른 포트는 서로 다른 저장소입니다. 기기를 옮길 때는 **자료와 백업 → 내 기록 백업하기**로 기록을 옮기세요.

## 현재 기능 · 2026-10-08

- 홈: 검색, 7개 분야, 작은 발견 카드, 최근 단어로 구성. 업무별 찾기는 제거했습니다. 낮은 휴대폰 화면에서는 발견 카드를 두 탭으로 전환합니다.
- 분야 순서: 마케팅·광고 → 개발·IT → 패션·섬유 → 영상·촬영 → 디자인 → 인사·재무 → 업무 공통.
- 첫 실행 맞춤 설정: 일하는 분야와 더 알고 싶은 분야를 각각 복수 선택. 실제 계정 로그인·기기 간 자동 동기화는 없습니다.
- 맞춤 설정은 내 업무 분야·관심 분야·보기 설정의 세 단계입니다. 직무·회사 유형·업무 바로가기 질문은 제거했습니다.
- 보기 설정에서 예문 먼저/뜻 먼저와 목록 간격을 선택합니다.
- 기본 검색은 선택한 업무 분야. 모든 분야·궁금한 분야·개별 분야로 바꿀 수 있습니다. 같은 검색 관련도에서는 업무 분야, 관심 분야 순으로 정렬합니다.
- 단어·별칭·한국어 줄임말·뜻을 설명하는 문장 검색, 종류·주제 필터, 목록 더 보기.
- 단어 상세: 뜻, 업계 예문, 주의점, 확인한 자료, 관련 용어, 다른 분야의 뜻.
- 단어장: 개인 메모, 업무별 모음, 단어·메모 검색, 분야/모음 필터, CSV 내보내기. 메모를 저장하면 해당 단어도 단어장에 담깁니다.
- 업무 도구: 원문 속 용어 형광펜 표시와 호버 설명, 최대 3개 뜻 비교, 최근 본 20개 뜻 및 최근 검색.
- 표시된 단어에 마우스를 올리면 분야·뜻·예문이 열리고, 단어와 설명창을 벗어나면 닫힙니다. 터치로 열고 바깥 터치로 닫을 수 있습니다. 키보드는 Tab으로 단어를 선택하고 ↓로 설명창에 들어가며 Esc로 닫습니다. 원문 수정·분야 변경 후 다시 찾기·지우기를 지원합니다.
- 같은 표현의 반복 위치와 업종별 뜻을 함께 찾고, 겹치는 표현은 긴 표현을 우선합니다. 원문의 줄바꿈·기호·전각 문자·조합형 한글을 유지합니다. 긴 문서는 원문 영역 안에서 스크롤하며 상세에서 돌아오면 그 위치를 복원합니다.
- 문서 도구는 최대 20,000자를 이 탭에서 비교합니다. 문장 의도 추론 기능은 아니며 입력문은 저장소에 기록하거나 서버에 전송하지 않습니다.
- JSON 백업: 설정·단어장·메모·최근 기록·비교 목록을 포함. 가져오기는 단어장과 메모를 합치고 백업의 맞춤 설정을 복원합니다. 같은 단어의 현재 메모는 유지합니다. 이전 버전 기록도 가져올 수 있습니다.
- 학습·게임 메뉴를 제거했습니다. 이전 학습 기록은 데이터 유실을 막기 위해 백업에만 보존합니다.
- 검색 목록의 더 보기 개수·스크롤·포커스는 상세에서 뒤로 갈 때 복원됩니다.

본문을 잘라내기 위해 페이지 스크롤을 잠그지 않습니다. 작은 화면·확대 글꼴·긴 사전 내용에서는 필요한 만큼 자연스럽게 스크롤됩니다.

## 2026-09-16 분야 분류 수정

회사에서 접할 가능성만으로 다른 분야의 전문 공정을 복제하지 않습니다. 패션의 상품 개발·생산·유통과 브랜드 마케팅·화보 협업은 유지하고, 전문 영상·음향·편집 공정은 해당 분야에서 찾도록 정리했습니다.

- 패션 2D는 평면 패턴 설계, 3D는 가상 의상·착장 시뮬레이션으로 설명·예문·별칭·검색 문장·근거를 함께 교체했습니다. 레이어도 의상 겹침 문맥으로 수정했습니다. 근거는 CLO 공식 도움말입니다.
- 패션에서 광고·영상 전문 항목 50개를 제외하고 원래 뜻이 있는 분야로 연결합니다. 키비주얼·ROAS·브랜드 매니저 등 패션 회사의 관련 실무 용어는 유지합니다. PT의 일반 발표 의미는 업무 공통으로 통합했습니다.
- 디자인에 복사된 의류 생산 조직 및 DI·컨폼 등 전문 피니싱 항목 8개, 업무 공통에 복사된 IT 전문 직무 3개도 정리했습니다. 먼저 전문 분야 오분류 61개를 정리했고, 이어서 동일한 뜻의 일반 업무 중복 625개를 공통으로 통합해 총 1765개 뜻이 남았습니다. 표제어 종류 1087개는 유지합니다.
- 기존 북마크·학습 기록·상세 링크는 `redirects`로 해당 뜻의 적절한 분야에 연결됩니다. 새 패션 학습 풀에는 제외 항목이 나오지 않습니다.
- `data/field_review.py`에서 검토 결과를 명시적으로 관리합니다. 이후 빌드에서도 같은 오분류가 다시 생기지 않도록 자동 테스트합니다.

일반 업무를 각 업종에 복사하지 않습니다. `field_review.py`는 공통에 같은 표제어·같은 뜻이 있으면 공통 항목으로 연결합니다. 광고주 제안 PT처럼 업종의 구체적 의미를 명시한 항목은 별도로 유지합니다. 일반 조직·직급·결재·발표 등도 업무 공통에서 찾습니다. 이전 2026-09-15 기록의 광범위한 중복 등록 방침은 이 분류 기준으로 대체했습니다.

## 데이터 추가

1. 공개 자료에서 뜻과 쓰임을 확인하거나, 뜻이 확실한 일반 지식을 직접 작성합니다. 불확실한 은어의 의미·영문 풀이는 추측해 등록하지 않습니다.
2. 회사·직무·공정·구어의 상세 확장은 `data/industry_detail.py`에 작성합니다. 출처가 있으면 `SOURCES`를 연결하고, 없으면 그룹의 source를 빈 문자열로 둡니다. 한국어 줄임말은 `data/korean_shortforms.py`, 그 외는 `data/slang.py`, `data/workplace.py` 또는 `data/expansion.py`의 `SOURCES`에 출처, URL, 자료 시점을 추가합니다.
3. `GROUPS`에 분야·종류·주제·출처와 항목을 추가합니다. 각 행은 다음 6개 칸입니다.

```text
표제어|영문|별칭1;별칭2|직접 쓴 뜻|직접 쓴 예문|검색 문장1;검색 문장2
```

4. 같은 의미도 실제로 쓰이는 분야마다 포함합니다. `workplace.py`와 `slang.py`의 그룹 첫 칸에는 쉼표로 여러 분야를 지정할 수 있습니다. 이미 등록된 뜻은 `workplace.COPIES`로 원문 뜻·메모·출처를 보존하며 다른 분야에 연결합니다. `slang.ALIAS_UPDATES`는 기존 ID와 뜻을 유지하며 별칭·근거를 보강합니다. 복사 후 그대로 발행하지 않고 대상 분야의 정의·예문·검색 문장·주석을 각각 검토합니다. 서로 다른 의미는 별도로 작성합니다. 표기 변형은 별칭에만 넣습니다. 불확실한 수집 후보는 검증 전에 배포 데이터에 넣지 않습니다.
5. 추가·수정한 항목을 분야별로 검토하고 `data/reviewed-meanings.json`의 해당 기록을 갱신합니다. 키 순서는 `scripts/check_editorial_review.py`의 `CONTENT_KEYS`, 내용 해시는 `signature(entry)`를 사용합니다. 해시는 변경 감지용이며 의미의 정확성을 자동 판정하지 않습니다. 검토하지 않고 전체 해시를 재생성하지 않습니다.
6. 다음 명령으로 검증·생성합니다.

```sh
python3 scripts/build_data.py
python3 scripts/check_editorial_review.py
node --test tests/core.test.js
```

빌드는 검토 기록에 없는 변경·추가가 있으면 발행 전에 중단합니다. `reviewed-meanings.json`은 자동 갱신하지 않습니다.

생성물은 `data/dictionary.json`, `data.js`, `data/COLLECTION.md`입니다. `index.html`의 스크립트 버전도 파일 내용에 맞춰 갱신하므로 변경된 데이터와 검색 코드를 다시 불러옵니다. `data/id-map.json`은 한번 배정한 단어 ID를 유지합니다. 항목 순서를 바꿔도 기존 책갈피가 다른 단어를 가리키지 않도록 이 파일을 보존하세요. 분야가 이동된 기존 ID는 `dictionary.json`의 `redirects`로 연결합니다. 표제어 자체를 바꾸려면 ID 대응도 함께 검토해야 합니다.

전체 HTML은 `index.html`, 화면과 동작은 `app.js`, 순수 검색·검증 로직은 `core.js`, 추가 스타일은 `app.css`에 있습니다. 기존 `build_preview.py`는 현재 데이터 빌드로 연결되며 기능 화면을 과거 정적 시안으로 덮어쓰지 않습니다.

## 같은 단어, 다른 의미 자동 연결

- `core.js`의 `contrastPairs`가 현재 데이터에서 비교 카드를 생성합니다. 새 표제어를 별도의 카드 목록에 등록할 필요가 없습니다. 별칭이 다른 항목의 표제어와 일치하는 경우도 연결합니다.
- `data/meaning_groups.py`는 동일한 정의에 같은 `meaningKey`를 부여합니다. 업종에 맞춰 다르게 설명했지만 같은 개념인 경우는 `data/meaning-equivalences.json`의 검토한 정의 묶음으로 합칩니다. 예문이나 출처의 차이로 의미를 나누지 않습니다.
- 의미 묶음은 단어 전체가 아닌 검토한 정의에만 적용합니다. 기존 단어에 새로운 뜻이 생겨도 기존 의미에 무조건 합치지 않습니다. 뜻을 다시 설명하는 데이터를 추가할 때는 원래 `meaningKey`를 유지하거나 해당 정의의 동등 관계도 검토합니다. 이 분류는 AI의 의미 추론이 아닙니다.
- 같은 의미의 업종별 복사, 같은 분야 안의 비교, 같은 정의는 카드에서 제외합니다. 단어·의미 조합마다 카드를 한 번만 만들고 두 개의 상세 링크를 유지합니다.
- 검증: 새 단어·별칭 자동 편입, 동일 의미 제외, 세 가지 뜻의 모든 조합, 관심 분야 선택, 항목 삭제, 한 바퀴 중복 방지. Python 의미 분류 검사 3개도 통과했습니다.
- 실제 브라우저에서 47개 조합을 한 바퀴 돌려 40개 단어가 표시되는 것을 확인했습니다. 카드 전환 중 검색 입력과 오늘의 단어는 유지됩니다.
